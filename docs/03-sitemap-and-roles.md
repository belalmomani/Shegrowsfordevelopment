# 03 — خريطة الصفحات والأدوار

## تطبيق المستفيدات (التنقل السفلي)
| الصفحة | المحتوى |
|---|---|
| الرئيسية | البرامج المفتوحة، تنبيهات حالة الطلبات |
| البرامج | بطاقات الدورات المنشورة فقط، وصفحة تفاصيل بالشروط والمقاعد وزر التقديم |
| طلباتي | الرقم المرجعي والحالة وسجل التغييرات (دون الملاحظات الداخلية) |
| فرص المشاركة | فرص التطوع والخبرة، وتسجيل ساعاتي |
| حسابي | الملف الشخصي، الإنجازات، الموافقات، طلب تصحيح/حذف البيانات، اللغة |

## لوحة الإدارة
لوحة المؤشرات · البرامج (والدورات) · المستخدمون · الطلبات · الحضور · قياس الأثر · التقارير · الصلاحيات · سجل التدقيق

## الأدوار (الصلاحيات الفعلية في `schema.sql`)
| الدور | يستطيع | لا يستطيع |
|---|---|---|
| مدير النظام | المستخدمون والأدوار والإعدادات وسجل التدقيق | تعديل بيانات البرامج والمؤشرات |
| إدارة المؤسسة | كل البرامج والطلبات والأعضاء، اعتماد المؤشرات، التقارير | إدارة المستخدمين التقنية |
| منسقة البرنامج | الدورات **المسندة إليها** فقط: الطلبات والحضور والتقييم والنتائج | دورات غيرها، اعتماد المؤشرات |
| مسؤولة قياس الأثر | تعريف المؤشرات والتحقق من الأدلة | قرارات القبول |
| مدققة/مانحة | التقارير المجمّعة المصرح بها فقط | البيانات الشخصية |
| عضوة/مستفيدة | ملفها وطلباتها وإنجازاتها | بيانات غيرها |
| متطوعة/خبيرة | ملفها والفرص وساعاتها | بيانات غيرها |

مبدأ أقل صلاحية: الصلاحيات الافتراضية ضيقة، والتوسيع يتم من شاشة الصلاحيات ويُسجَّل في التدقيق.

## قواعد لا تتغير
- المسودات والدورات التجريبية لا تظهر للجمهور (`is_public = 0` و`status = draft`).
- التسجيل ≠ المشاركة ≠ الحضور ≠ الإكمال: جداول منفصلة (`applications` → `participations` → `attendance`).
- لا يُرسل قبول تلقائي: تغيير الحالة قرار جهة مخوّلة ويُسجَّل في `application_status_history`.
- الأشخاص الفريدون: الهوية في `members` مع قيد تفرد على الهاتف والبريد المطبّعين، وأداة دمج (`merged_into_id`).
