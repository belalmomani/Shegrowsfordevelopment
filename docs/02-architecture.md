# 02 — التقنية والاستضافة والتكاليف

## القرار المقترح (المسار 1)
| الطبقة | الاختيار | السبب |
|---|---|---|
| Backend | PHP 8.x بدون إطار ثقيل، PDO + استعلامات مُهيّأة | يعمل على الاستضافة المشتركة، وهو ما تعمل به مشاريعك الحالية |
| قاعدة البيانات | MySQL/MariaDB، InnoDB، utf8mb4 | قيود مفاتيح أجنبية وفهارس تمنع التكرار |
| الواجهة | HTML/CSS/JS عادي، RTL أولا، متجاوب | بلا أدوات بناء، سهل الصيانة |
| الاتصال | REST API ‏`/api/v1` بصيغة JSON | واجهة واحدة للوحة الإدارة وPWA وأندرويد |
| التطبيق | PWA قابل للتثبيت، ثم حزمة Android عبر TWA | تطبيق واحد بدل ثلاثة |
| الكود | مستودع GitHub **خاص** | بيانات حساسة وقاصرون |

**التكلفة المتوقعة:** صفر للتطوير والاختبار. نطاق ومضيف إنتاجي مدفوع (اختياري) عند الإطلاق الفعلي، ولا يُشترى شيء دون موافقتك.

## GitHub لا يشغّل PHP
GitHub يحفظ الكود فقط. التشغيل يتم على استضافة PHP/MySQL. طريقة النشر: ترفع محتويات المستودع إلى الاستضافة (FTP كما تفعل الآن)، ويمكن لاحقا إضافة نشر تلقائي عبر GitHub Actions إن رغبت.

## ما يجب التحقق منه قبل اعتماد InfinityFree للإنتاج
هذه نقاط للفحص العملي في الاستضافة نفسها وليست أحكاما مؤكدة:
- نسخة PHP المتاحة وإضافة PDO وامتدادات الملفات المطلوبة.
- إرسال البريد (قد لا يعمل `mail()`)، لذا الإشعارات داخل التطبيق هي الأساس، والبريد اختياري.
- عدم وجود مهام مجدولة (cron)، لذا لا نعتمد عليها في الوظائف الأساسية.
- شهادة HTTPS على النطاق الفرعي، وهي شرط لـ PWA وTWA، وملف `/.well-known/assetlinks.json` يجب أن يكون متاحا.
- حدود حجم الرفع وعدد الطلبات اليومية.
- النسخ الاحتياطي: لا نعتمد على نسخ المضيف. نضع سكربت تصدير SQL يدويا/عبر لوحة الإدارة ونختبر الاستعادة.

**تحذير مهم:** الاستضافة المجانية مناسبة للتجربة. قبل إدخال بيانات مستفيدات حقيقيات (ومنهن قاصرات) على الإنتاج، يُنصح بمضيف مدفوع بنسخ احتياطي موثوق. القرار لك وللمؤسسة.

## المسار البديل (المسار 2): Supabase
واجهة ثابتة + قاعدة بيانات Postgres مع صلاحيات على مستوى الصفوف (RLS). نتحقق من الحصص الحالية قبل اعتماده. يتطلب إعادة كتابة المخطط لـ Postgres. لم نختره لأنه أبعد عن بيئة عملك.

## الأمن (كيف تُفرض الصلاحيات)
MySQL لا يملك RLS، لذا تُفرض الصلاحيات في **طبقة الخادم**:
1. كل مسار API يمر عبر `Policy` تتحقق من الصلاحية **ومن النطاق** (الدورات المسندة لهذه المنسقة فقط).
2. الاستعلامات تُقيَّد بالنطاق في SQL نفسه (`JOIN cycle_team`)، وليس بالإخفاء في الواجهة.
3. مستخدم قاعدة بيانات واحد بصلاحيات DML فقط (دون DROP/ALTER) في الإنتاج.
4. كلمات المرور بـ `password_hash` (Argon2id إن توفر وإلا bcrypt)، وجلسات بملف تعريف ارتباط `HttpOnly; Secure; SameSite=Lax`، ورمز CSRF لكل طلب كتابة، وتحديد محاولات الدخول عبر `login_attempts`.
5. الملفات المرفوعة: قائمة امتدادات بيضاء، فحص MIME وحجم، اسم عشوائي، وحماية المجلد بـ `.htaccess`.
6. لا توجد كلمة مرور افتراضية: المدير الأول يُنشأ عبر سكربت تثبيت لمرة واحدة.
